 1 결론 요약
 핵심 결론 3가지
 ① 현 플랫폼은 "SME 검증" 절반만 갖춘 상태로 분석됩니다. 직무정의·Task·Skill·수행요건에 대한 적합성 평가/의견/수정 제안, 자동 저장, 재검토 흐름, RLS 기반 권한 통제는 이미 구현되어 있으나, 착수보고 11면의 핵심 방법론인 과업별 투입 비중(FTE) 배분(직무 단위 합계 100%) 이 기능·스키마·화면 어디에도 없습니다. 이 상태로는 계약 산출물 1-(4) 「조직별 업무량·업무분장 분석」과 3-(4) 「적정 인력 산정 모델」의 원천 데이터를 생산할 수 없습니다.
 ② 개편은 "재작성"이 아니라 "5대 모듈 증축"으로 수행할 것을 권장합니다. 현 스택(Vite SPA + Supabase + GitHub Pages)을 유지하고, 참고 레포(job-analysis-seoyon)에서는 온보딩·단계형 마법사·검증 게이트·문의 채널·검토 워크벤치·운영(마감/리마인더) 패턴만 이식 합니다. 참고 레포의 스택(TanStack Start SSR·Cloudflare Workers)으로의 전환은 비개발자 유지보수와 CLI 작업 리스크를 키우므로 배제합니다.
 ③ 이 플랫폼 자체가 착수보고·계약의 이행 증빙이 되도록 설계합니다. 화면 문구는 착수보고 수정안 문언을 그대로 사용하고(예: "업무량은 과업별 투입 비중 배분 방식이며 개인별 시간 실측이 아님"), Export는 계약 산출물 번호와 1:1로 매핑하며, 응답 소요 시간을 앱이 실측해 11면의 "직무당 약 ○○분(착수 후 확정)"을 채울 근거를 확보합니다.

 1-2. 판단의 전제
 방법론 일치가 최우선 기준입니다. 착수보고는 "HCG가 초안을 먼저 작성하고 SME가 확인·보완"하는 방식을 명시합니다 11면 . 현 레포는 이 패러다임(관리자 업로드 초안 → SME 검토)과 이미 일치하므로 유지·강화하고, 참고 레포의 "응답자가 처음부터 작성"하는 6단계 마법사는 구조만 차용하고 내용은 검증형으로 재설계 합니다.
 실제 코드 수정은 Claude CLI가 수행합니다. 본 문서 §10~§11이 Phase 0~5의 작업 순서·완료 기준·복붙용 프롬프트를 제공하며, 각 요구사항에는 근거 칩( 착수보고 면 계약 산출물 레포 파일 경로 )을 달아 CLI가 원문·원본 코드를 직접 대조할 수 있게 했습니다.
 공수 표기는 Claude CLI 작업 세션 기준의 추정치 이며, 파일럿(Phase 5) 결과에 따라 조정이 필요합니다.
 2 개편 배경·요구사항 — 착수보고가 곧 제품 스펙

 범위 종료선 — 플랫폼에도 동일하게 적용 
 착수보고의 산출 수준 원칙(설계 요소·적용 방향 제시 수준, 규정 문안·산식·기준표 확정은 후속 별도 과제) 15~16면 하단 고정행 은 플랫폼에도 그대로 적용됩니다. 즉 플랫폼은 FTE 분포의 수집·집계·Export까지 수행하며, 전사 적정 인력의 확정 수치 계산이나 조직별 증감 판단 기능은 만들지 않습니다. 이 경계를 지켜야 웹 도구가 과업 범위를 스스로 확장하는 역효과를 막을 수 있습니다.

 6 화면별 상세 기획
 각 화면은 목적 → 구성 요소 → 핵심 동작 → 화면 문구(착수보고 문언 고정) 순으로 명세합니다. Claude CLI는 이 절의 문구를 UI 카피로 그대로 사용해야 합니다(원칙 P1).
 6-1. SME | 시작 가이드·온보딩 신규 — R3·R4
 목적 — 계약 1-(3)의 "작성가이드 포함"을 화면으로 이행하고, 조사 방식·FTE 개념·예상 소요를 시작 전에 각인합니다.
 구성 — 4장 카드(가로 진행): ① 조사 취지와 방식 ② 무엇을 하게 되는지(5단계 미리보기) ③ 투입 비중(FTE)이란 ④ 소요·저장·문의 안내. 최초 로그인 시 필수 통과(마지막 카드의 "시작하기"), 이후 상단 "가이드 다시 보기"로 상시 재열람.
 핵심 동작 — 가이드 통과 시각을 기록( profiles.guide_completed_at ). 마법사 각 단계 상단에도 해당 단계 축약 가이드를 접이식으로 상시 노출.
 소요 실측(R4) — 마법사 진입~이탈을 review_sessions 에 기록해 직무당 실소요 중앙값을 산출합니다. 화면에는 "예상 소요 약 N분"(관리자 설정값)만 표시하고, 실측치는 관리자 화면에서만 노출합니다(SME 압박 방지).
 화면 문구(고정) — 카드 ①·③은 착수보고 문언 그대로 
 카드 ①: "직무·과업 초안을 HCG가 먼저 작성했습니다. 여러분은 초안이 실제 업무와 맞는지 확인·보완 해 주시면 됩니다. 처음부터 작성하는 조사가 아닙니다." 11면 
 카드 ③: "투입 비중(FTE)은 지난 1년 기준, 이 직무 수행에 실제로 들어간 시간의 상대적 비중 을 과업별로 배분하는 것입니다. 직무 단위 합계가 100%가 되면 됩니다. 개인별 소요 시간을 실측하는 방식이 아니므로 , 시계를 재실 필요가 없습니다." 11면 Step 2 
 카드 ④: "예상 소요는 직무당 약 N분이며, 입력은 자동 저장됩니다. 중간에 나가셔도 이어서 진행됩니다. 막히는 부분은 화면 우측 하단 '문의하기'로 남겨 주세요."
 6-2. SME | 검증 마법사 5단계 개선 — R1·R2·R6
 현행 단일 장문 폼을 5단계 마법사로 재구성합니다. 좌측(모바일에서는 상단 가로) StepChecklist가 단계·완료 상태를 상시 표시하고, 각 단계는 검증 게이트 를 통과해야 다음으로 이동합니다. 기존 자동 저장(2.5초)·적합성 컨트롤·제안 편집기는 재사용합니다 src/pages/sme-review/controls.tsx .
 단계 | 내용(기존 자산 재사용 표기) | 다음 단계 이동 게이트 |

 STEP 3 상세 — 투입 비중(FTE) 배분 화면
 대상 목록 — STEP 2 결과가 실시간 반영됩니다: 유지 Task + SME가 추가한 신규 제안 Task(라벨 표시). 삭제 제안한 Task는 목록에서 제외 하되 "삭제 제안 n건 제외됨" 안내를 표시합니다.
 입력 방식 — 행별 ±5% 스텝퍼 + 직접 숫자 입력(0~100, 정수) + 행별 미니 막대. 시작점 옵션 "균등 배분으로 시작"(잔여 없이 n등분 후 미세 조정) 제공 — 백지 공포를 줄이는 P3 장치.
 합계 게이지 — 우측(모바일 하단 고정)에 합계 링과 잔여 % 상시 표시. 100% 도달 시 "다음" 활성화, 초과 시 초과분 적색 표시.
 품질 가드 — ⓐ 단일 Task 100% 배분 시 확인 모달("이 직무의 시간이 사실상 한 과업에 쓰인다는 의미입니다. 맞습니까?") ⓑ 0% Task 존재 시 제출 요약에 목록 표시(허용은 하되 인지시킴) ⓒ 5% 미만 다수 분산 시 안내 문구.
 겸직·비중 인식 지원 — 헤더에 기간 기준("지난 1년")과 "이 직무에 쓴 시간만을 100%로 봅니다(타 직무 겸직 시간 제외)"를 고정 표기 — SME 1~2인 응답 편차를 줄이는 정의 통일 장치(R6).

 산출물 명세표와의 연결 
 과업범위 합의서의 산출물 명세표(착수보고 수정안 C장 체크리스트) 작성 시, E1~E3의 필드 정의를 "검수 기준" 열에 그대로 인용할 수 있습니다. 예: 1-(4) 검수 기준 = "E2 Export의 직무×조직 피벗이 승인 응답 기준으로 산출 가능할 것". 플랫폼 명세가 곧 검수 기준이 되므로 문언 분쟁 여지가 줄어듭니다.
 10 구현 로드맵 — Phase 0~5
 순서 논리: 보안(0) → 데이터(1) → SME 경험(2) → 관리자(3) → 운영·산출(4) → 파일럿·확정(5) . 각 Phase는 독립 배포 가능 단위이며, 완료 기준(DoD)을 충족해야 다음 Phase로 이동합니다. 공수는 Claude CLI 작업 세션 기준 추정치입니다.
 P0 보안 기반 추정 0.5일 · 선행 필수 
 S1~S3 + audit_logs 골격. DoD : ① noindex·robots.txt 배포 확인 ② 신규 SME 계정이 첫 로그인에서 비밀번호 변경 없이는 어떤 화면에도 진입 불가 ③ 시드 계정 제거 절차가 README에 반영 ④ npm run typecheck && npm run build 통과.
 P1 데이터 모델 확장 추정 0.5~1일 
 §7-1 신규 테이블 8종 + RLS + submit_review · decide_review RPC. 조직 마스터·SME 명부 업로드(4시트 양식). DoD : ① 마이그레이션이 빈 DB와 기존 DB 양쪽에서 순서 실행 성공(가산성 검증) ② SME 계정으로 타인 review의 FTE 행 insert 시도가 RLS로 거부 ③ FTE 합계 99.99에서 submit_review가 부족 항목을 반환.
 P2 SME 검증 마법사 + FTE + 가이드 추정 2~3일 · 최대 공수 
 §6-1·§6-2 전체 — 마법사 골격·StepChecklist·게이트, STEP 3 FTE 화면(그림 6-A), 시작 가이드, 예시 팝오버·용어 힌트, 문의 작성, 소요 세션 기록. 기존 섹션 컴포넌트는 단계 안으로 이식(로직 재사용). DoD : ① STEP 2에서 Task 추가·삭제 제안 시 STEP 3 목록이 즉시 동기화 ② 합계 100% 미만이면 다음·제출 모두 차단(클라+서버) ③ 마법사 중도 이탈 후 재진입 시 동일 단계·값 복원 ④ 모바일(390px)에서 STEP 3 조작 가능 ⑤ 화면 문구가 §6 고정 문언과 일치.
 P3 관리자 워크벤치·현황 추정 2일 
 §6-3 ⓐⓑ — 진행 매트릭스, 비교 뷰(그림 6-B), 승인/반려, 워크숍 자동 규칙·수동 플래그, 문의 인박스. DoD : ① 반려 시 SME 화면에 사유 배너 노출·해당 review만 편집 해제 ② FTE 비중 차 ≥ 20%p 행 하이라이트 ③ 자동 플래그 사유가 reasons 배열에 축적 ④ 계열사 필터가 전 화면에서 일관 동작.
 P4 운영·산출 추정 1~2일 
 Export 5종(§9), 마감 D-day, 리마인더 메일(Edge Function + Resend, 미설정 시 시뮬레이션), 수동 스냅샷. DoD : ① E1~E5가 XLSX·CSV·JSON으로 다운로드 ② E2 피벗 수치가 원본 응답 수기 검산과 일치(표본 3개 직무) ③ Resend 키 없이도 발송 흐름이 mail_logs(simulated=true)로 완결.
 P5 파일럿·확정 추정 1일 + 파일럿 기간 
 내부 2~3인 파일럿 → 소요 실측으로 "직무당 약 ○○분" 확정(R4) → 문구·기본값 조정 → 접근성·부하(동시 30~50명 응답) 점검 → 시드 계정 제거·운영 계정 전환. DoD : 파일럿 체크리스트 전 항목 통과 + PM 확인 4건(§12) 반영.
