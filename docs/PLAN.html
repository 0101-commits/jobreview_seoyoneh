1결론 요약

핵심 결론 3가지

① 현 플랫폼은 "SME 검증" 절반만 갖춘 상태로 분석됩니다. 직무정의·Task·Skill·수행요건에 대한 적합성 평가/의견/수정 제안, 자동 저장, 재검토 흐름, RLS 기반 권한 통제는 이미 구현되어 있으나, 착수보고 11면의 핵심 방법론인 과업별 투입 비중(FTE) 배분(직무 단위 합계 100%)이 기능·스키마·화면 어디에도 없습니다. 이 상태로는 계약 산출물 1-(4) 「조직별 업무량·업무분장 분석」과 3-(4) 「적정 인력 산정 모델」의 원천 데이터를 생산할 수 없습니다.

② 개편은 "재작성"이 아니라 "5대 모듈 증축"으로 수행할 것을 권장합니다. 현 스택(Vite SPA + Supabase + GitHub Pages)을 유지하고, 참고 레포(job-analysis-seoyon)에서는 온보딩·단계형 마법사·검증 게이트·문의 채널·검토 워크벤치·운영(마감/리마인더) 패턴만 이식합니다. 참고 레포의 스택(TanStack Start SSR·Cloudflare Workers)으로의 전환은 비개발자 유지보수와 CLI 작업 리스크를 키우므로 배제합니다.

③ 이 플랫폼 자체가 착수보고·계약의 이행 증빙이 되도록 설계합니다. 화면 문구는 착수보고 수정안 문언을 그대로 사용하고(예: "업무량은 과업별 투입 비중 배분 방식이며 개인별 시간 실측이 아님"), Export는 계약 산출물 번호와 1:1로 매핑하며, 응답 소요 시간을 앱이 실측해 11면의 "직무당 약 ○○분(착수 후 확정)"을 채울 근거를 확보합니다.

1-2. 판단의 전제

  • 방법론 일치가 최우선 기준입니다. 착수보고는 "HCG가 초안을 먼저 작성하고 SME가 확인·보완"하는 방식을 명시합니다11면. 현 레포는 이 패러다임(관리자 업로드 초안 → SME 검토)과 이미 일치하므로 유지·강화하고, 참고 레포의 "응답자가 처음부터 작성"하는 6단계 마법사는 구조만 차용하고 내용은 검증형으로 재설계합니다.
  • 실제 코드 수정은 Claude CLI가 수행합니다. 본 문서 §10~§11이 Phase 0~5의 작업 순서·완료 기준·복붙용 프롬프트를 제공하며, 각 요구사항에는 근거 칩(착수보고 면 계약 산출물 레포 파일 경로)을 달아 CLI가 원문·원본 코드를 직접 대조할 수 있게 했습니다.
  • 공수 표기는 Claude CLI 작업 세션 기준의 추정치이며, 파일럿(Phase 5) 결과에 따라 조정이 필요합니다.
